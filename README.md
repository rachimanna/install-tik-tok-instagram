# Бот для скачивания видео и фото из TikTok и Instagram

Telegram-бот на Python 3.11+ и aiogram 3. Пришлите ему ссылку, и он отправит видео или фото:

- **TikTok**: видео по полной или короткой ссылке (`vm.tiktok.com`, `vt.tiktok.com`, `tiktok.com/t/…`).
  Бот старается взять версию без водяного знака. Если её нет, видео подписывается
  «⚠️ Чистая версия недоступна — это видео с водяным знаком».
- **TikTok фото-посты (слайдшоу)**, включая ссылки `/photo/`: бот присылает фото в исходном
  качестве. Музыку слайдшоу бот не отправляет.
- **TikTok Stories** (видео и фото): обрабатываются тем же загрузчиком, но скачаются, только если сторис ещё доступна
  и TikTok отдаёт её загрузчику (подробнее в разделе «Ограничения»).
- **Instagram**: Reels, видео и фото из публичных публикаций. Карусель приходит целиком,
  видео и фото в исходном порядке.
- **Звук из видео**: следом за видео приходит его звуковая дорожка аудиофайлом с названием,
  автором и обложкой. В Telegram он открывается в музыкальном плеере. Отключается через
  `SEND_AUDIO=false`.
- **Сторис Instagram** (видео и фото, «Актуальное»): нужен подключённый служебный аккаунт,
  см. раздел «Сторис Instagram».
- Если файлов несколько, они приходят альбомами (по 10), а за ними идёт сообщение со списком
  (разрешение и размер каждого файла) и кнопкой **«📁 Скачать оригиналы файлами»**.
- Под каждым видео есть цветные кнопки **«📁 Скачать оригинальным файлом»** (зелёная) и
  **«🔗 Открыть источник»** (синяя). Цвет кнопок появился в Bot API 9.4, в старых клиентах кнопки
  будут обычными.

Все сообщения бота на русском. Пока идёт работа, бот обновляет одно сообщение со статусом:
«🔎 Проверяю ссылку…» → «⬇️ Скачиваю видео…» → «📤 Отправляю…». После отправки это сообщение удаляется.

## Настройка

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Скопируйте `.env.example` в `.env` и впишите `BOT_TOKEN`. Остальные параметры можно не менять.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен бота (обязательно) |
| `BOT_MODE` | polling | `polling` — бот сам опрашивает Telegram; `webhook` — Telegram присылает обновления на HTTPS-адрес (для Render) |
| `WEBHOOK_BASE_URL` | `RENDER_EXTERNAL_URL` | публичный https-адрес для режима webhook |
| `WEBHOOK_SECRET` | — | строка, из которой выводится секретный токен вебхука |
| `PORT` | 8080 | порт HTTP-сервера в режиме webhook (Render задаёт сам) |
| `MAX_UPLOAD_MB` | 50 | лимит размера файла. Облачный Bot API принимает до 50 МБ |
| `TELEGRAM_API_URL` | — | адрес своего [Telegram Bot API сервера](https://github.com/tdlib/telegram-bot-api). С ним лимит до 2000 МБ |
| `MAX_CONCURRENT_DOWNLOADS` | 3 | одновременных загрузок на весь бот |
| `MAX_TASKS_PER_USER` | 1 | одновременных задач на одного пользователя |
| `DOWNLOAD_TIMEOUT_SECONDS` | 180 | таймаут одной загрузки |
| `SEND_TIMEOUT_SECONDS` | 300 | таймаут отправки файла в Telegram |
| `FILE_TTL_MINUTES` | 60 | сколько хранить файл для кнопки «📁» |
| `CACHE_MAX_MB` | 2000 | максимальный размер кэша файлов |
| `SEND_AUDIO` | true | отправлять после видео его звук отдельным аудиофайлом |
| `TIKTOK_ALLOW_WATERMARK_FALLBACK` | true | если чистой версии нет, отправлять видео с водяным знаком (с пометкой). При `false` бот сообщит, что чистой версии нет |
| `YTDLP_COOKIES_FILE` | — | необязательно: cookies.txt **вашего служебного** аккаунта, если площадка требует вход |
| `YTDLP_PROXY` | — | необязательно: прокси для yt-dlp |

Бот никогда не спрашивает у пользователей пароли от соцсетей. Токен и cookies не попадают в логи.

Для работы нужен **ffmpeg**: он склеивает видео и звук Instagram без перекодирования, читает
разрешение и делает превью.

## Сторис Instagram

Instagram отдаёт сторис только вошедшему пользователю, поэтому боту нужен аккаунт. Пароли
пользователей бот не спрашивает: в бот загружаются cookies **вашего отдельного служебного
аккаунта**. Пока аккаунт не подключён, на ссылку на сторис бот отвечает, что сторис недоступны.
Посты, Reels и фото работают и без этого.

Поддерживаются ссылки:
- `instagram.com/stories/<user>/<id>/` — одна сторис (видео или фото);
- `instagram.com/stories/<user>/` — все текущие сторис пользователя;
- `instagram.com/stories/highlights/<id>/` и `instagram.com/s/…` — «Актуальное».

Как подключить **с iPhone** (без компьютера):
1. Установите из App Store бесплатное расширение Safari **Cookie-Editor** и включите его:
   **Настройки → Safari → Расширения → Cookie-Editor**, разрешите доступ к instagram.com.
2. Откройте в Safari instagram.com и войдите в **отдельный** служебный аккаунт.
3. Нажмите значок расширений в адресной строке → Cookie-Editor → экспорт в формате
   **Header string** (строка вида `sessionid=…; csrftoken=…`). Строка скопируется.
4. Откройте в Safari dashboard.render.com → сервис → **Environment → Add Environment Variable**:
   имя `INSTAGRAM_COOKIES`, значение — вставьте строку. **Save Changes**.

`INSTAGRAM_COOKIES` принимает строку заголовка, JSON-экспорт расширения, готовый cookies.txt
или просто значение `sessionid`. Нужна обязательно cookie `sessionid`, иначе бот не запустится
и напишет об этом в логах.

Как подключить **с компьютера**:
1. Заведите отдельный аккаунт Instagram. Основной не используйте: Instagram может ограничить
   или заблокировать аккаунт, через который ходит бот.
2. Войдите в него в браузере на компьютере.
3. Выгрузите cookies в формате Netscape. Например, через yt-dlp (браузер при этом лучше закрыть):
   ```bash
   yt-dlp --cookies-from-browser firefox --cookies all-cookies.txt --skip-download "https://www.instagram.com/"
   grep -E '^#|instagram\.com' all-cookies.txt > cookies.txt
   rm all-cookies.txt
   ```
   `--cookies-from-browser` читает cookies всех сайтов, поэтому вторая команда оставляет только
   instagram.com. Вместо `firefox` можно указать `chrome`, `edge` и др.
4. Передайте файл боту одним из способов:
   - `YTDLP_COOKIES_FILE=/путь/к/cookies.txt` (VPS, Codespaces);
   - `YTDLP_COOKIES_B64=` и содержимое файла в base64: `base64 -w0 cookies.txt`.
     На Render это проще всего: **Environment → Add Environment Variable**. Секретные файлы
     Render (`/etc/secrets/…`) по сообщениям на форуме Render не всегда читаются из контейнера
     с непривилегированным пользователем, а бот работает именно так.
5. Cookies со временем устаревают. Если бот пишет, что вход в аккаунт бота устарел, повторите
   шаги 2–4.

Учтите: бот откроет сторис закрытых профилей, на которые подписан служебный аккаунт, любому,
кто пришлёт ссылку. Не подписывайте его на закрытые профили, которые не хотите раскрывать.

Как это устроено: экстрактор сторис в yt-dlp (`InstagramStoryIE`) разбирает каждую сторис, но
в результат кладёт только видео, фото-сторис выбрасываются. Бот перехватывает внутренний метод
`_extract_product` и получает все сторис по порядку, включая фото. Если в ссылке есть id сторис,
отправляется только она. Если в новой версии yt-dlp этого метода не станет, бот продолжит
скачивать видео-сторис, а фото-сторис перестанут скачиваться.

## Запуск на Render

В репозитории есть `Dockerfile` (Python 3.12 + ffmpeg) и `render.yaml` (Blueprint).

1. Зайдите на [dashboard.render.com](https://dashboard.render.com) и подключите GitHub-аккаунт.
2. **New → Blueprint** → выберите репозиторий `install-tik-tok-instagram`.
3. Render покажет сервис `tiktok-instagram-bot` и попросит значение `BOT_TOKEN`. Вставьте токен
   от @BotFather. `WEBHOOK_SECRET` сгенерируется сам.
4. Нажмите **Apply**. Сборка Docker-образа занимает несколько минут. Когда в логах появится
   `Webhook mode: listening on port …`, напишите боту `/start`.

Как это работает: на Render бот запускается в режиме `BOT_MODE=webhook`. Адрес сервиса берётся
из переменной `RENDER_EXTERNAL_URL`, которую Render задаёт сам. При старте бот регистрирует
вебхук `https://<сервис>.onrender.com/telegram/webhook` с секретным токеном. Запросы без этого
токена отклоняются (401). Проверка работоспособности доступна по `/health`.

**Бесплатный тариф (`plan: free`):**
- сервис засыпает после 15 минут без входящих запросов. Новое сообщение будит его, но первый
  ответ приходит с задержкой (обычно до минуты). Telegram повторяет доставку вебхука, так что
  сообщение не теряется;
- после сна или передеплоя кэш файлов пропадает, и кнопки «📁» под старыми видео отвечают,
  что ссылку нужно прислать заново;
- 512 МБ памяти, поэтому в `render.yaml` стоит `MAX_CONCURRENT_DOWNLOADS=2`.

Чтобы бот не засыпал, смените в настройках сервиса Instance Type на платный (Starter и выше).
Можно и создать **Background Worker** с `BOT_MODE=polling`, но воркеры на Render бесплатно не
доступны. Актуальные цены смотрите на сайте Render.

## Запуск в GitHub Codespaces

1. В репозитории: **Code → Codespaces → Create codespace on main**. Контейнер сам поставит ffmpeg
   и зависимости (`.devcontainer/devcontainer.json`).
2. Токен лучше хранить как секрет Codespaces: **Settings → Secrets and variables → Codespaces →
   New repository secret**, имя `BOT_TOKEN`. Можно и через файл: `cp .env.example .env`, затем
   вписать токен в `.env`.
3. Запуск:
   ```bash
   python -m bot
   ```
4. Тесты:
   ```bash
   pytest
   ```

Codespace засыпает после периода бездействия, и бот при этом останавливается. Для постоянной
работы используйте VPS.

## Запуск на Linux VPS (Ubuntu 24.04, Debian 12 или новее)

Нужен Python 3.11+. В Ubuntu 22.04 стоит Python 3.10, там установите более новую версию отдельно.

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip ffmpeg git

sudo useradd --system --create-home --home-dir /opt/video-bot videobot
sudo -u videobot git clone https://github.com/rachimanna/install-tik-tok-instagram.git /opt/video-bot/app
cd /opt/video-bot/app
sudo -u videobot python3 -m venv /opt/video-bot/.venv
sudo -u videobot /opt/video-bot/.venv/bin/pip install -r requirements.txt

sudo -u videobot cp .env.example /opt/video-bot/.env
sudo -u videobot nano /opt/video-bot/.env          # впишите BOT_TOKEN
sudo chmod 600 /opt/video-bot/.env
```

Проверка вручную:

```bash
cd /opt/video-bot/app
sudo -u videobot bash -c 'set -a; . /opt/video-bot/.env; set +a; /opt/video-bot/.venv/bin/python -m bot'
```

Автозапуск через systemd:

```bash
sudo cp deploy/video-bot.service /etc/systemd/system/video-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now video-bot
journalctl -u video-bot -f
```

TikTok и Instagram часто меняют сайты, поэтому yt-dlp стоит регулярно обновлять:

```bash
/opt/video-bot/.venv/bin/pip install -U "yt-dlp[default,curl-cffi]"
sudo systemctl restart video-bot
```

## Как это устроено

- **Выбор качества.** Берётся лучший доступный формат со звуком в пределах лимита Telegram.
  Видео не перекодируется и не масштабируется. Для Instagram лучший видеопоток и лучший звук
  склеиваются ffmpeg без перекодирования (remux). Для TikTok выбираются только форматы, где видео
  и звук уже вместе. Отдельную дорожку `audio` у TikTok составляет музыка, и склеивать её нельзя.
- **Водяной знак TikTok.** yt-dlp помечает форматы с водяным знаком (`download`, `download_addr`)
  в `format_note` как `watermarked`. Бот сначала выбирает непомеченные форматы (поток плеера) и
  подписывает их «✨ Без водяного знака». Если остались только помеченные, видео подписывается
  как версия с водяным знаком. Если подтвердить отсутствие знака нельзя, бот так и пишет.
- **Фото TikTok.** yt-dlp для фото-постов отдаёт только музыку, сами фото он не извлекает.
  Фото лежат в данных страницы (`itemStruct.imagePost.images[].imageURL.urlList`, те же поля
  использует gallery-dl). Экстрактор TikTok в yt-dlp и так скачивает эти данные, и бот
  перехватывает их, не делая второго запроса. Предпочитается JPEG, при ошибке пробуется
  следующая ссылка из списка. Перехват опирается на внутренний метод yt-dlp
  (`_extract_web_data_and_status`). Если в новой версии yt-dlp его не станет, фото TikTok
  перестанут скачиваться, а видео продолжат.
- **Звук из видео.** ffmpeg вырезает звуковую дорожку из уже скачанного видео, нового запроса
  к площадке нет. AAC (так почти всегда у TikTok и Instagram) копируется в `.m4a` без
  перекодирования, MP3 тоже копируется. Другие кодеки (Opus, Vorbis) перекодируются в AAC
  192 кбит/с, иначе Telegram не покажет их в плеере. Если у видео нет звука, аудио не
  отправляется. Если аудио не удалось отправить, видео всё равно приходит, а ошибка остаётся
  в логе. Несколько аудиофайлов (из карусели) приходят одной группой после альбома.
- **Фото Instagram.** Берётся самый большой вариант из `image_versions2.candidates`.
- **Отправка фото.** Фото уходит как фото, если Telegram его примет (JPEG/PNG до 10 МБ, сумма
  сторон до 10000). Иначе (WebP, HEIC, слишком большое) — файлом без перекодирования. Адрес
  каждого фото проверяется: только https и только публичные IP.
- **Лимиты Telegram.** Облачный Bot API принимает файлы до 50 МБ. Бот не берёт формат больше
  лимита, если есть подходящий поменьше, и прерывает загрузку, когда она превышает лимит.
  Ошибку «файл слишком большой» он не повторяет.
- **Кнопка «📁».** Скачанный файл переносится в кэш на `FILE_TTL_MINUTES`. При первом нажатии он
  уходит документом как есть (`disable_content_type_detection`). Затем бот сохраняет Telegram
  `file_id`, удаляет локальный файл, и повторные нажатия используют `file_id`. Кэш и `file_id`
  хранятся в памяти, поэтому после перезапуска старые кнопки ответят, что ссылку нужно прислать заново.
- **Безопасность ссылок.** Принимаются только `http(s)`, домены `tiktok.com`/`instagram.com` и их
  поддомены, порты 80/443, ссылки без логина и пароля. Короткие ссылки бот раскрывает сам, без
  автоматических переходов. Каждый редирект заново проходит все проверки, а все IP-адреса хоста
  должны быть публичными: localhost, частные сети, link-local, 169.254.169.254 и т. п. запрещены.
  У yt-dlp включены только экстракторы TikTok и Instagram (`allowed_extractors`), поэтому
  «generic»-загрузка произвольных адресов невозможна.
- **Нагрузка.** Глобальный семафор ограничивает число загрузок, есть лимит задач на пользователя.
  yt-dlp работает в пуле потоков вне event loop. Таймаут останавливает загрузку через progress-hook.
  У каждой загрузки своя временная папка, она удаляется и после успеха, и после ошибки.
  При запуске удаляются остатки от прошлого процесса.

### Как сменить или добавить загрузчик

Создайте класс с методами `supports(link)` и `download(link, workdir, cancel)` (см.
`bot/providers/base.py`) и добавьте его в список в `bot/providers/__init__.py`. Первый провайдер,
который поддерживает ссылку, и выполняет загрузку. Сторонние платные API в проект не включены:
их адреса, параметры и тарифы нужно брать из официальной документации конкретного сервиса, а ключ
передавать через переменную окружения.

## Ограничения

- **TikTok Stories.** В yt-dlp 2026.8.19 нет отдельного экстрактора для сторис TikTok (это проверено
  по исходному коду). Ссылка на сторис открывается по тому же адресу `/@user/video/<id>`, что и
  обычное видео, и обрабатывается общим экстрактором TikTok. Скачается ли сторис, зависит от того,
  что вернёт TikTok. Если не скачается (истекла или не отдаётся), бот так и скажет и не выдаст
  ошибку за «видео удалено».
- **Сторис Instagram** работают только с подключённым служебным аккаунтом (см. раздел
  «Сторис Instagram»). На реальном аккаунте это не проверено: из среды разработки Instagram
  недоступен.
- **Фото в TikTok Stories**: работают, только если в данных сторис есть `imagePost`, как у
  фото-постов. На реальной сторис это не проверено.
- Закрытые аккаунты, удалённые публикации и контент с возрастными ограничениями скачать нельзя.
  Бот показывает понятное сообщение.
- TikTok и Instagram могут ограничивать запросы с IP-адресов дата-центров. Тогда помогает
  обновление yt-dlp, а иногда `YTDLP_COOKIES_FILE` или `YTDLP_PROXY`.
- Файлы больше 50 МБ можно отправлять только через собственный Bot API сервер (`TELEGRAM_API_URL`).
- Если на сервере нет прямого DNS (только HTTP-прокси), проверка IP-адресов не пройдёт и бот
  откажется раскрывать короткие ссылки.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты работают без сети. Они проверяют:
- распознавание ссылок и отказ для чужих доменов, IP, портов, `user:pass@` и т. п.;
- раскрытие редиректов: проверку каждого шага, блокировку приватных адресов, ограничение цепочки;
- фото: слайдшоу TikTok (без скачивания музыки, JPEG предпочтительнее WebP, переход на запасную
  ссылку), фото-посты и смешанные карусели Instagram, лимит размера, проверку адресов фото;
- звук: копирование AAC без перекодирования, видео без звука, перевод Opus в AAC, порядок
  «видео → аудио», отключение, сбой отправки аудио не ломает видео;
- альбомы: разбиение по 10, отправку неподходящих фото файлом, кнопку «📁» для группы файлов;
- выбор формата на настоящем yt-dlp (с синтетическими форматами TikTok/Instagram) и пометку водяного знака;
- разбор ошибок yt-dlp в понятные сообщения;
- сценарий целиком: один статус, удаление временных папок после успеха, ошибки и таймаута,
  лимиты, отказ от повторной отправки слишком большого файла;
- кнопку «📁» на настоящем aiogram с подменённым API Telegram: отправку документом, переиспользование
  `file_id`, истёкший срок;
- сторис Instagram: ссылки (включая «Актуальное» и `/s/`), фото-сторис, выбор сторис по id,
  истёкшая сторис, ответ без подключённого аккаунта, cookies из base64 с правами 600;
- скрытие токена, cookies и подписанных ссылок в логах;
- режим вебхука: `/health`, отказ без секретного токена, доставку обновления в обработчик.
